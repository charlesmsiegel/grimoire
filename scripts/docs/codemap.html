Repository tooling: three roots, one purpose

This package is the repository's out-of-band tooling — 3,454 lines that never run inside the server. It deliberately spans three directories, because the code was filed by who wrote it rather than by what it is: scripts (CI harnesses and launchers), backend/scripts (offline store operations that need the grimoire package), and one script belonging to a repository-local authoring skill.

Two of these are load-bearing for correctness rather than convenience: scripts/verify_templates.py is a CI gate, and scripts/validate_partition.py encodes a review check that was previously done by hand.

scripts/validate_partition.py394Checks a proposed function-to-file mapping for intra-package import cycles, reading the partition tables straight out of a spec document. Written because three rounds of review kept doing it by hand.
backend/scripts/redownload_chub.py112Re-imports every externally-linked character version. Failures are per-version, so one bad card never stops the sweep.
scripts/unix, scripts/windows185Launchers and the Android bootstrap.
The riskiest property of this package is that nothing tests it. scripts/verify_templates.py is a gate in .github/workflows/ci.yml: if it silently stops checking something, the prompt/template contract it guards degrades with no signal at all. It carries 159 branches and no test of its own. The same is true of backend/scripts/ingest_scene.py, which writes into a real user store through the absorb pipeline.
Scope of this atlas. The analyzers were scoped to scripts, so backend/scripts/ingest_scene.py, backend/scripts/redownload_chub.py and the skill script are counted in this package's grade and theory but do not appear in the Inventory, Dependencies or Hotspots tabs. The repository atlas covers them.
