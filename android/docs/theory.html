Judge 1

Theory: Android hosts the same local web application inside a WebView and gives its embedded backend a process lifetime independent of the Activity. The native shell supplies the operating-system capabilities the web application cannot own: foreground execution, notification navigation, file selection and extracted runtime assets.

Instead of: A separate native product with duplicated backend state and UI is another coherent approach; this package deliberately embeds the existing backend, frontend and templates so product behavior remains shared.

Judge 3

Theory: Android hosts the same Python library and React product inside one app process, adapting only files, server startup, WebView integration and OS run notifications. The process owns the backend, the activity owns presentation, and a service tracks live runs so work can continue when the activity is absent. A stable loopback origin links packaged web assets to client recovery state across ordinary relaunches.

Instead of: A separate native Android product with a remote server would also be coherent, but the build packages current shared sources and the runtime resolves their filesystem paths locally; native code is a host and lifecycle adapter.
