Judge 3

Theory: The frontend is a navigation and editing surface over server-owned records, with separately owned client state for unconfirmed sends and remembered reads. Identity, freshness and operation lifetime determine when data may be displayed or acted on; a component unmount does not mean the server operation ended. Shared React contexts and focused hooks keep shell navigation, play recovery and domain editing in their appropriate lifetimes.

Instead of: A fully offline client database with local-first mutation would also fit a desktop-style interface, but this code treats server confirmation and run discovery as authoritative and preserves only enough local state to recover the user interaction.
