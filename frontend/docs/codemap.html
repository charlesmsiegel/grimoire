Data writers and coordination

The server remains authority for records; the browser stores bounded remembered answers, pending text and preferences. Client mutations invalidate remembered reads before and after settlement, then semantic event channels refresh persistent chrome. Run completion has a later invalidation point because detached writes may follow the initiating HTTP response. frontend/src/api/client.ts:331, frontend/src/api/client.ts:344, frontend/src/api/client.ts:443, frontend/src/api/client.ts:95.

Local persistence is shared but not transactional. Each tab merges one key over current localStorage before writing; there is no compare-and-swap across tabs. Another device's scene rename also cannot rekey this browser's pending record. Both constraints are documented in the owner rather than guaranteed away by React state. frontend/src/runs/RunRegistryProvider.tsx:83, frontend/src/runs/RunRegistryProvider.tsx:161.
