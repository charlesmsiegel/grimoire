A conventional React SPA with one enormous exception

frontend/src is 194 files and 49,145 lines of TypeScript — a Vite + React + react-router single-page app, tested with vitest and Testing Library, with about half its lines in co-located .test.tsx files. It talks to the backend through exactly one module, frontend/src/api/client.ts, and it is disciplined: the repository documents a list/detail page pattern and the record-editing screens follow it.

The exception is frontend/src/routes/CampaignView.tsx: a single function component that opens at line 251 and closes at line 4236. It is the play screen, the top hotspot in the whole repository by a factor of three, and the one place where the package's structure is not conventional at all.

Reading order

  1. frontend/src/api/client.ts — the contract with the backend, and the most-changed file in the package (170 commits). Note the two notify helpers at the top: campaign and config mutations announce themselves so the persistent sidebar cannot show stale rows.
  2. frontend/src/App.tsx — routing and the persistent shell.
  3. frontend/src/components/EntityEditor.tsx or frontend/src/components/GreetingEditor.tsx — the canonical list/detail page: a sticky rail, a read-only detail view, and an explicit Edit step. Every record screen is supposed to look like this.
  4. frontend/src/api/stream.ts — SSE parsing, where a scene turn arrives.
  5. frontend/src/routes/CampaignView.tsx — last, and budget time for it.

The list/detail pattern

flowchart LR
  N["+ New ..."] -->|"opens the form directly"| E["mode = edit"]

  V -->|"Edit button in the sidebar"| E

Records are never editable by default; the read-only view renders the body as Markdown and puts related-record links in the sidebar as clickable chips. Documented in the repository's conventions and implemented in frontend/src/components/EntityEditor.tsx.

Testing and coverage

The suite is 83 test files and 1,533 tests. Coverage is genuinely measured — 82.4% of statements, 78.1% of branches, 75.5% of functions, 85.8% of lines, over 108 measured files — and the configuration in frontend/vite.config.ts is unusually careful about why: it pins the istanbul provider rather than v8 (with a measured note that v8 reported 47 of 68 files as 100% covered when no test imported them) and sets all: true so an untested module counts as 0% instead of vanishing from the report.

One test in this suite fails outside UTC. frontend/src/routes/CampaignsView.test.tsx:56 builds a timestamp with toISOString() and strips the trailing Z, then expects "last played 2 days ago". frontend/src/routes/CampaignsView.tsx:11 parses a zone-less stamp as local time, so the elapsed interval shifts by the machine's UTC offset. Verified: 1 failed / 1,532 passed in local time, 83 files / 0 failed under TZ=UTC. CI runs ubuntu-24.04, so it is green there and has been all along.

Risk ranking

1. frontend/src/routes/CampaignView.tsx. The component opens at line 251 and closes at line 4236: 28 useState calls, 7 useEffect calls, 64 hooks in total, 695 branches in the file. Churn 155 over 24 months and a hotspot score of 107,880 — the next file scores 32,264. It simultaneously owns transcript paging, streaming, staged-edit review, the cast and dossier columns, roll proposals and alternates. Its test file (frontend/src/routes/CampaignView.test.tsx, 7,076 lines) is the largest file in the frontend, which is the honest signal of how much behaviour is trapped in one component. Note that frontend/src/components/play exists and holds 890 lines of extracted pieces — the decomposition has started and stalled.
2. A timezone-dependent test that CI structurally cannot catch. frontend/src/routes/CampaignsView.test.tsx:56 fails on any machine west of UTC and passes on ubuntu-24.04. The underlying code at frontend/src/routes/CampaignsView.tsx:11 parses a zone-less stamp as local time; real backend stamps carry a Z so production is correct today, but the fallback is a latent off-by-one-timezone in a user-visible string. Cheapest fix is the fixture; the durable fix is to make the parser reject or normalize a zone-less stamp.
3. 21 floating promises and 14 swallowed rejections. Calls like frontend/src/components/CharacterEditor.tsx:448, frontend/src/components/CharacterEditor.tsx:654 and frontend/src/components/EntityEditor.tsx:144 start async work nothing awaits, and .catch(() => {}) patterns at frontend/src/components/GreetingEditor.tsx:50 and frontend/src/components/ResponsePresetPicker.tsx:116 discard the error and report success. In a local app with no error reporting, a silently-dropped save is invisible until the user notices the data is gone.
4. Seven empty catch blocks, one of them on the streaming path. frontend/src/api/stream.ts:72 is the one worth reading first: the SSE parser is where a scene turn arrives, and it is the one artifact the backend cannot regenerate.
5. 80 weak-assertion-only tests. Tests whose only assertion is existence or truthiness. Against 1,533 tests that is a small fraction, but they concentrate the risk that coverage numbers overstate what is actually verified — a line can execute under a test that asserts nothing about it.
