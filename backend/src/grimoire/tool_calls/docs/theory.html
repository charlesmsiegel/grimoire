Judge 1

Theory: A tool call is a provider-neutral declared operation with validated parameters, a model-supplied request and a bounded result, separate from the inference loop that decides when to execute it. The package preserves provider-specific continuation state only for its originating provider and model, and keeps ownership of timed-out worker threads until they actually return.

Instead of: Executing callbacks directly inside each provider stream would avoid neutral messages but mix transport parsing with effects and leak abandoned worker capacity; this package instead separates declarations, collected calls, message lowering and executor ownership.

Judge 3

Theory: Tool calling is a neutral protocol of declared functions, validated argument objects, bounded results and provider-provenanced turn history. Calls and results are correlated even when provider IDs are rewritten, while signed or opaque state is echoed only to its originating provider/model. Execution ownership and bounded workers support read/proposal tools without letting provider adapters become application executors.

Instead of: Provider-specific dictionaries passed throughout the application could also perform tool calls, but would spread message syntax, provenance and argument validation into every loop; this package makes those facts one portable contract.
