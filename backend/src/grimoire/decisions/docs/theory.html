Judge 1

Theory: A decision is a closed question about supplied evidence, answered only by caller-declared values, with missing, refused, abstained and erroneous answers kept distinct. Structured replies and native endpoint reports are two observations of that same question algebra, and lowering must preserve meaning rather than invent an answer the provider did not give.

Instead of: An untyped JSON object with task-specific defaults and ad hoc prose parsing is another plausible implementation; the code instead shares a typed algebra, portable schema and tolerant-but-noninventive reader across all callers.

Judge 2

Theory: A decision is a finite, caller-defined question whose answer must preserve what the model actually said, including refusal, abstention and unreadability. Predicate, choice, score, ranking, selection and conditioned pair are distinct question forms that share validation, schema budgets and a transport-independent result vocabulary.

Instead of: Parsing arbitrary model prose into caller-specific defaults would be another way to make decisions; this contract instead makes the permissible answer space explicit and never invents an answer when evidence is missing.

Judge 3

Theory: A decision is a closed question whose caller defines the legal answers before a model is asked. Its neutral algebra separates a reported answer, abstention, refusal, unreadability and failure, and translates structured or native evidence without inventing missing certainty. Composite questions preserve the semantics of conditioning, selection and partial order across the provider representations that can carry them.

Instead of: A generic JSON extraction facility could also answer classification requests, but would leave legal-answer semantics and missing-evidence interpretation to every caller; this package makes those distinctions part of the request/result algebra.
