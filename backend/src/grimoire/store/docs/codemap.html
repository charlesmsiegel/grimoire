Files hold facts; campaigns hold divergence

The store is a domain layer over a user-owned library, with world records inherited until a campaign edits, deletes or detaches them. Identity, reviewed mutation and atomic publication matter more than CRUD convenience. SQLite accelerates derivations without owning inventory: backend/src/grimoire/store/overlay.py:3, backend/src/grimoire/store/compiled.py:3.

Copy-on-write publication

sequenceDiagram
  participant C as Caller
  participant O as Overlay
  participant L as Campaign lock
  participant W as World record
  participant A as Atomic writer
  C->>O: Materialize or prepare flat record
  O->>L: Acquire shared hold
  O->>O: Read strict identity ledgers
  alt Campaign copy already exists
    O-->>C: Existing ownership
  else Inherited record is visible
    O->>W: Read selected original bytes
    O->>O: Validate group bindings and reserve base hash
    O->>A: Write complete prepared record
    A->>A: Flush, fsync, replace
    O-->>C: Campaign now owns copy
  else Missing or tombstoned
    O-->>C: Not found
  end

The source hash belongs to the original selected bytes, not the edited result or a second world read. Publication and binding validation share one campaign hold (backend/src/grimoire/store/overlay.py:855, backend/src/grimoire/store/overlay.py:865, backend/src/grimoire/store/overlay.py:890). Atomic replacement preserves one record, not every surrounding ledger as one filesystem transaction (backend/src/grimoire/store/atomic.py:225).

Prepare, commit, resume

sequenceDiagram
  participant R as Review client
  participant T as Commit token and epoch
  participant J as Positional journal
  participant W as Domain writers
  R->>T: Save approved review with token
  alt Token already spent
    T-->>R: Original stored result
  else Fresh or unfinished commit
    T->>J: Claim and inspect progress
    J->>W: Apply pending steps only
    W-->>J: One outcome per edit
    alt Outside value changed during interruption
      J-->>R: Fresh conflict row
    else Steps settle
      J->>T: Persist finished result
      T-->>R: Replayable outcome
    end
  end

Review generation itself does not create the commit entry; the epoch travels in the token. On resume, a target/value pair is exempt only if this commit actually wrote it, preventing stale conflict verdicts from erasing an outside edit (backend/src/grimoire/store/commits.py:15, backend/src/grimoire/store/commits.py:32, backend/src/grimoire/store/absorb/apply.py:53).

Failure and concurrency boundaries

Atomic writes clean their temporary file on failure, while metadata preservation is best effort (backend/src/grimoire/store/atomic.py:152, backend/src/grimoire/store/atomic.py:246). Display reads may fail soft on malformed ledgers; identity-changing writes require strict ledgers, because treating corruption as “attached” can import unrelated world content (backend/src/grimoire/store/overlay.py:388, backend/src/grimoire/store/overlay.py:428). Locks serialize cooperating local writers; sync clients retain their own consistency semantics (backend/src/grimoire/store/atomic.py:20).
