The database, written by hand

backend/src/grimoire/store is a filesystem-as-database layer: 172 Python modules, 33,200 lines, implementing over a directory of Markdown and JSON everything a database would otherwise provide — atomic writes, locking, inheritance, migrations, tombstones, backups and search. It is the largest package in the repository, larger than the entire frontend.

Its shape is a wide facade over a mostly-flat set of record modules. Roughly 84 modules sit directly at the top level (one per record kind or concern) with 14 subpackages for the concepts that grew past one file — context, absorb, scenes, modules, campaigns, weather, sheets. There is no ORM, no repository abstraction, and no service layer between it and the routes.

The four modules that define the package

ModuleWhy it matters
backend/src/grimoire/store/paths.py:47 home() — the resolution rule for the whole store: GRIMOIRE_HOME, then a bootstrap pointer, then the default. Every path in the package descends from it.
backend/src/grimoire/store/atomic.py The only write path. Temp file, fsync, os.replace, with Windows sharing-violation retries. Its header is explicit about the guarantees it does not make.
backend/src/grimoire/store/locks.py The campaign lock domain, declared as three data structures rather than prose, with a 30s timeout at backend/src/grimoire/store/locks.py:323.
backend/src/grimoire/store/overlay.py Copy-on-write campaign-over-world resolution — 964 lines, 172 branches, and the package's top hotspot.

Reading order

  1. backend/src/grimoire/store/paths.py — where the data lives.
  2. backend/src/grimoire/store/atomic.py — how a record is written.
  3. backend/src/grimoire/store/overlay.py — how a record is found. The hardest idea in the package: campaign copies shadow world originals, with two distinct kinds of absence (tombstoned and detached) and two different overlay rules (whole-directory for actors, per-file for everything else).
  4. backend/src/grimoire/store/locks.py — what may run at the same time.
  5. backend/src/grimoire/store/context — the prompt-assembly subpackage. Start at backend/src/grimoire/store/context/assemble.py, which holds the section catalog, then backend/src/grimoire/store/context/world_state.py (the package's third hotspot, 1,089 lines).
  6. backend/src/grimoire/store/absorb — turning a played scene into proposed state edits. backend/src/grimoire/store/absorb/materializer.py and backend/src/grimoire/store/absorb/apply.py are the two halves.
  7. Skip unless you need them: the per-kind record modules (birthdays, taglines, thumbs, …). They are small, similar, and mostly obvious once the four modules above are understood.

Why the top level is flat. The package resists a layered structure because its unit of organization is the record kind, not the operation: each kind gets a module owning its read, its write and its path. The four cross-cutting modules above are the exception, and they are precisely the ones with guard tests attached. Whether that is the right theory for a package this size is the question the Theory page takes up.

Four rules hold this package together, and all four are enforced by tests

This package would be dangerous if its rules were conventions, because it has no type system standing between a caller and a corrupted transcript. Instead each rule is compiled into a test that parses the package's own AST and fails the build, with an explicit escape hatch that must carry a stated reason.

The enforced rules

RuleGuardEscape hatchVerdict
Every record write goes through atomicbackend/tests/test_atomic_guard.pyatomic-okenforced
No inheritable record is read off a raw campaign rootbackend/tests/test_overlay_guard.pyoverlay-okenforced
Filesystem access goes through the resolversbackend/tests/test_paths_guard.py, backend/tests/test_path_guard_store.pypaths-okenforced
Campaign-scoped mutators take campaign_lock(cid)backend/tests/test_lock_domain_guard.pylock-domain-okenforced, with a backlog
Only hold_all may hold two campaign locksbackend/tests/test_lock_order_guard.pylock-order-okenforced
Module graph acyclic; imports at module scope; cross-package imports bind submodulesbackend/tests/test_import_guard.pyimport-okenforced
The escape hatches are designed not to be cheap. A marker with no reason fails deliberately, and each guard caps how many may exist. That converts "I'll add a suppression" from a one-character edit into a reviewable claim.

Risk ranking

1. backend/src/grimoire/store/overlay.py is the package's hotspot and its hardest idea at the same time. 964 lines, 172 branches, 43 commits in 24 months, hotspot score 7,439 — the highest in the package. It encodes four states (campaign copy, tombstoned, detached, inherited) and two different overlay rules, and the guard that protects it can only check that other modules do not bypass it; nothing checks the resolution logic inside it beyond ordinary tests.
2. UNREVIEWED is a list of campaign mutators nobody has confirmed. backend/src/grimoire/store/locks.py:298. The guard permits it to shrink but not grow, which is the right shape for a backlog — but its entries are by construction the exact bug class the lock domain exists to prevent, and the module header records that rolls really was outside the domain until it joined.
3. Complexity concentrates in the absorb pipeline. backend/src/grimoire/store/absorb/apply.py:83 trips four separate high-severity detectors at once (cyclomatic, cognitive, nesting depth and function length), and backend/src/grimoire/store/absorb/apply.py:594 two more. Absorb is the step that writes model-proposed edits into the user's world, so it is a poor place for a function nobody can hold in their head.
4. Search is O(corpus) per query, by choice. backend/src/grimoire/store/search.py walks every file on every query, with extraction memoized on (path, mtime, size). The docstring argues this is right at "hundreds of files, one user, local disk" — a defensible trade that is also an undocumented scaling limit for a library that grows by one scene per session forever.
5. 58 swallowed exceptions. The ones I read are individually argued in docstrings and correct (a lost activity stamp must not fail a completed write; one malformed preset must not abort a registry scan). But 58 is enough that "it's always argued" is a claim about the package nobody has verified in one pass.
