The model boundary: one facade, three providers, and all the prompt text

This package is the seam between grimoire and any language model — 1,518 lines of Python plus the 102 files in templates, which is why it is defined as a package spanning two directories. It is small, and it is the only part of the backend where an external service can fail.

Its organizing idea: no prompt string exists in code. backend/src/grimoire/prompts.py renders every string sent to a model from templates through Jinja with StrictUndefined, so a template that references a variable nobody passes raises instead of quietly rendering nothing.

An optional dependency handled properly. backend/src/grimoire/claude_agent.py imports the Claude Agent SDK inside a try that catches ImportError and a broken install separately, binds the exception targets to empty tuples rather than None (because except None raises while except () simply never matches), and defers the failure to stream(). It has to: the SDK lives in an extra Android does not install, and backend/src/grimoire/llm.py imports this class at module scope, so an exception escaping here would stop the app from starting.
The LLM Ops tab is empty, and that is a detector limitation. The analyzer finds call sites by vendor SDK method name; grimoire calls OpenRouter over raw httpx and reaches Claude through the Agent SDK's query, so it reports zero call sites for the package whose entire job is calling models. Read backend/src/grimoire/llm.py directly instead.
Scope of this atlas. The analyzers were scoped to backend/src/grimoire with routes, store and assets excluded, which is the only way to isolate these top-level modules. That means backend/src/grimoire/main.py appears in the tabs here although it is graded under grimoire-api, and templates does not appear at all, because it is a sibling directory. Its 102 files are counted in this package's roots for grading and theory.
