Judge 1

Theory: Provider APIs are different wire spellings of typed attempts, portable schemas and neutral message content, while templates own the language supplied to models. Provider adapters translate those values and report what was actually observed without making library policy decisions.

Instead of: Provider conditionals embedded at every feature call site would also work initially; the code instead centralizes protocol spelling and keeps prompt text editable apart from the data-gathering code.

Judge 3

Theory: Inference interoperability is a translation problem: typed targets and neutral messages describe intent, while provider adapters lower that intent into each endpoint and prompts render application-owned instructions. Model facts, limits, usage and errors keep their provenance rather than being invented from missing fields. Templates remain editable data and provider clients remain independent of the library.

Instead of: A universal provider client with one supposedly common wire shape would be coherent, but the code preserves different message placement, native decisions, opaque tool state and portable dependency constraints in explicit adapters.
