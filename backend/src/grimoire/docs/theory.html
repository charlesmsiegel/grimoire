Judge 1

Theory: This unit models the boundary between a storytelling app and a language model: everything grimoire says to a model is authored text held as data (templates/, rendered from store facts at send time, editable live without a restart), and everything a model says back is a bounded stream of text chunks. One facade turns a user-chosen connection record into that stream — idle-bounded, heartbeat-ticked, retried and failed-over while nothing has yet reached the player, and accounted for in a ledger — no matter which of three providers serves it. The model deliberately stops at text: no tool calls, no non-text frames, no opinion about what a prompt means.

Instead of: The other coherent reading is that llm.py is a provider-agnostic *reliability* layer (retry, backoff, fallback, idle timeouts, connection cleanup) that happens to sit near a Jinja wrapper, and that templates/ is a separate concern joined to it only by a directory listing. I rejected it because the resilience rules are stated and gated in domain terms rather than RPC terms: a timeout is excluded from RETRYABLE_KINDS so 'giving up after N seconds' keeps meaning the number the user set (backend/src/grimoire/llm.py:57-63), retrying stops the instant prose reaches the player because duplicated text is worse than an error (backend/src/grimoire/llm.py:345-357), and a long Retry-After is abandoned because it 'holds a scene hostage' (backend/src/grimoire/llm.py:76-86). Those are decisions about a person watching a scene generate, not about HTTP — the same subject the templates half serves, which is why the two halves share one theory and one verification posture (scripts/verify_templates.py for wiring, evals/ for whether the text still works).

Judge 2

Theory: This unit models the single wire between grimoire and a language model, in both directions: outbound, every word a model will read is authored as data in templates/ and rendered by a 37-line Jinja seam, so no Python file writes model-facing text; inbound, one facade turns three unlike vendor transports into one contract — an async stream of text deltas, an idle bound, a normalized failure taxonomy, and a per-call accounting row. The world it models is not 'HTTP to an AI provider' but 'a solo storyteller's turn must either arrive or fail quickly and legibly, on somebody else's flaky infrastructure, and be attributable afterwards' — which is why the retry rule is gated on whether text has already reached the reader (llm.py:323) rather than on any transport property, and why every constant is argued against a proxy, a rate limiter, or a bill. Where it stops is text: messages are strings in, strings out, with no room for tools, images, or a second channel.

Instead of: The obvious alternative reading is that these are two unrelated things filed together — templates/ a content directory, llm.py a resilience/transport layer that could equally be httpx middleware or a vendor SDK shim, with prompts as opaque strings its callers happen to pass. I rejected it because the code refuses that split at its most load-bearing point: `_resilient` decides whether a retry is legal from `sent` — whether a delta has reached the caller (llm.py:323) — which no transport layer can know, and `_guard` distinguishes a provider keep-alive from a facade heartbeat because only the prompt-facing side knows the difference matters (llm.py:202). Both halves are one rule applied to two directions of one wire: everything vendor-specific and everything text-specific stops at this line.

Judge 3

Theory: This unit models a generation as two separable problems: what is said, and how it is delivered. Everything the app says to a model is data — Jinja files under templates/ that a maintainer edits with no restart and no code change (prompts.py:1, templates/README.md:1) — while llm.py is one facade that makes three unlike providers behave as a single stream of text deltas that is idle-bounded, retried only while the caller has seen nothing, failed in one error taxonomy, and metered in one ledger. The invariants it exists to hold are stated in the code itself: a wedged upstream must become an LLMError rather than a held connection (llm.py:202), a retry must never duplicate text already on the wire (llm.py:345), and a route's failure must be attributable to the connection the user actually chose (llm.py:438).

Instead of: The other coherent reading is the ordinary one: llm.py as an HTTP-client wrapper with retry, and templates/ as a resources folder for strings. I rejected it because the code repeatedly refuses it. openrouter.py:88 deliberately *removes* the transport's read timeout so the facade can own the bound — a client wrapper would keep it; the adapters yield empty strings for content-free frames purely to feed a facade-level liveness clock they cannot see (openrouter.py:103, claude_agent.py:156); and templates/scene/system.j2:4 records that the top-level template stopped composing its own sections so that one render path could feed both the prompt and the inspector. Those are decisions about a shared model of a turn, not about plumbing. The transport reading also cannot explain llm_usage.py:21, where cache counts are defined as slices of the prompt rather than additions to it — a semantic commitment two providers with opposite wire conventions are both bent to meet.
