Judge 1

Theory: This unit models the HTTP surface of a single-user, local app whose database is a folder of markdown files: one module per noun of the world (worlds, campaigns, scenes, characters, entities, mechanics, weather), plus a generic /{kind} entity surface whose existence makes registration ORDER itself a modelled, tested invariant rather than an accident. Most routes are deliberately thin translations of store exceptions into status codes; the parts that are not thin are there because only an in-flight request knows facts the store cannot — that a scene's newest turn has displaced this one, that the caller walked away mid-generation, that a save is a retry of one that already half-landed. So the unit's real subject is the lifecycle of one request against an unlocked, syncable, human-editable store.

Instead of: The other coherent reading is 'routes are a pure adapter; all policy lives in store/' — which the file layout half-suggests, since common/models/streaming hold no routes and every handler delegates. I rejected it because the unit repeatedly and explicitly keeps request-scoped policy at this layer and records why: _Budget is 'deliberately absorb's policy rather than the LLM facade's' because only the caller of a sequence knows which steps are droppable (backend/src/grimoire/routes/scenes.py:935); _bounded_call is refused to absorb for the same reason (backend/src/grimoire/routes/common.py:209); turn ownership is in-process because it distinguishes two turns inside one backend, which is what a player generates (backend/src/grimoire/routes/streaming.py:53). Under the pure-adapter reading all of that is misplaced; under the request-lifecycle reading it is exactly where it belongs.

Judge 2

Theory: This is the boundary where a browser's requests become operations on a folder of markdown files that the user may also be editing, syncing, or opening from a second device — so it owns everything about a request the store cannot see: whether anyone is still waiting, how long a generation may run, which turn currently owns a scene, and what a half-finished request is allowed to leave behind. URL space is carved one router per domain noun (worlds, campaigns, scenes, mechanics, greetings, entities) with a deliberately generic `/{kind}` surface last, and the app assembly adds the cross-cutting facts no single handler can know: campaign activity stamping, the 409 for a busy store, and an SPA fallback that stops at /api. Where the model stops is stated rather than implied: one process, one user, no cross-file journal, and micro-second crash windows that are disclosed instead of closed.

Instead of: The other coherent reading is 'a thin CRUD adapter over store/ — one endpoint per store function, HTTP verbs mapped onto file operations.' Most of the small modules (usage, search, modules, weather) read exactly that way. I rejected it because the code's centre of mass contradicts it: post_absorb fans four LLM phases out under a wall-clock budget, put_chronicle runs a reserve/resume/epoch commit protocol, _chat_stream arbitrates turn ownership against a cancelled socket, and the rolling-summary block reconciles a stored summary against a transcript that moved. None of those have a store counterpart to adapt to; under the thin-adapter reading they would all look like code in the wrong file, whereas under the request-lifetime reading they are the layer's actual subject and their placement is argued in situ.

Judge 3

Theory: This unit is the HTTP boundary of a single-user, local, file-backed tabletop-RP tool: it projects the store onto two scopes — a world (the authored library) and a campaign (the copy-on-write overlay actually played) — and owns the concerns only a boundary can own, namely which turn a scene currently belongs to, what happens to half-generated prose when a provider fails or a player hits Cancel, wall-clock ceilings on multi-call LLM sequences, optimistic-concurrency preconditions against a folder Dropbox may also write, and what counts as 'campaign activity'. Its governing judgment, stated over and over, is that the scene transcript is the one artifact that cannot be regenerated, so every ambiguous failure resolves toward keeping text and reporting honestly rather than toward tidiness. Route registration order is treated as part of the model, not an accident, because the generic /{kind} surface capturing any third segment is a deliberate design choice with a checked consequence.

Instead of: The other coherent reading is 'a thin FastAPI adapter over store/ — request bodies in, JSON out, store exceptions mapped to status codes', with the interesting content all downstream in store/. I rejected it because the largest and most-reasoned code here is not translation: _fence_stream's finalize/on_error/on_abort triad and the _turn_tokens claim (streaming.py:276, streaming.py:68) encode turn-ownership policy the store deliberately cannot hold (its leaves take roots, not cids); _Budget (scenes.py:935) is explicitly absorb's policy rather than the LLM facade's; _CampaignActivityStamp (main.py:162) exists precisely because no store function all campaign mutators pass through. Each of those documents the store-level alternative it rejected, so the adapter reading is one the code argues against by name.
