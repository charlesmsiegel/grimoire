Judge 1

Theory: The API coordinates named work against a captured library subject, while a browser connection is only one observer of that work. Routes validate and reserve before mutation, detached runs own failure and cancellation, and replayable frames let a client recover the outcome of its attempt.

Instead of: Keeping a generation inside the lifetime of its HTTP request would be simpler, but it cannot preserve work or resolve ambiguous sends after navigation and phone suspension; the run registry deliberately owns that lifetime.

Judge 3

Theory: The HTTP application exposes a local library and coordinates long-running play as owned runs, separating the lifetime of work from the lifetime of the browser socket. A request admits and reserves an operation before it mutates; the app owns client pools, provider health, scheduling and cache warming. The API translates domain outcomes to transport responses rather than making provider transports own application state.

Instead of: A conventional request-scoped generation service would cancel work when a socket vanishes, but the reservation, replay and runner abstractions deliberately give turns their own lifetime and subject identity.
