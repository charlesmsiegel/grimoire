Judge 1

Theory: The backend suite treats a throwaway library and a controlled provider as an executable model of the product, and probes compatibility, faults and concurrency at its public operations. Frozen historical stores represent input the current implementation did not produce; scripted replies and cassettes separate ordered scenarios from request-matched scenarios.

Instead of: A suite dominated by live provider calls or regenerated snapshots would test a moving environment and could bless its own regressions; the code uses synthetic fixtures and preserved historical inputs instead.

Judge 3

Theory: The backend suite is an executable collection of library and orchestration contracts, built from temporary stores and scripted external boundaries. Provider fakes represent admissible or hostile replies, while real adapters and route lifespans are retained when those boundaries are the subject. Synthetic recordings prove handling and grader sensitivity, not model quality.

Instead of: A live-provider acceptance suite would also exercise the product, but would make privacy, cost, timing and model drift part of the ordinary gate; this suite instead controls those inputs and separately exposes their limits.
