# Authored rumors (063)

The headless `RumorLibrary` queues a single authored sender-to-recipient edge. Its source is confirmed evidence held by the sender at the authored Moment. The exact transmitted text may differ; provenance, distortion, confidence, attribution, and route constraints are director-auditable. The queue does not change an event or ruling and receipt creates no belief. An authorized caller may separately admit a belief through 020. Retelling requires a new edge sourced from the sender's received report.

The caller supplies an explicit campaign-local clock id and unit, nonnegative sent/due ticks, and a knowledge Moment; ticks do not measure Moment sequence. `advance` requires the same clock, persists a nondecreasing watermark even without a delivery, and accepts explicit proximity, affiliation, channel and attention conditions. It processes at most `limit` (1–500, default 100) eligible due edges in `(due_tick, communication_id)` order; blocked entries remain pending and do not starve eligible entries. Remaining capacity reconciles blocked edges with staged attempts. The returned counts and `trace` are director-only. No distance, relationships or attention are inferred.

An NPC send requires an issued trusted application handle and explicit director control. A PC send requires the current controller's issued trusted human handle and a typed, exact speech contribution matching actor, scene and turn, admitted using current stored controls. A retry reconciles the original proof. Store permissions must separately authorize evidence writes; a trusted handle is not a grant.

`outbox` returns immutable sender-safe authored details without route, distortion, provenance, delivery status or receipt time. `actor_knowledge` requires `requested_by` and an issued trusted application handle for director access or the current controller’s issued trusted human handle for actor access; the campaign must match the actor. It is the supported actor projection for rumor-enabled callers: it replaces this domain's delivery-dependent sent reports with stable sends at the persisted proposition Moment, and retains normal received evidence. Human reads use the existing controller projection, separating earlier controllers’ beliefs as inherited; director reads retain the ordinary actor projection. **Raw 020 sender projections are unsupported in rumor-enabled runtime** because they reveal a change when the report is appended. Runtime, context-pack and campaign-reader wiring to this adapter is a required integration dependency: do not expose rumor authoring through the existing application until those readers use it. This slice makes no application-level privacy or UI-completion claim.

Requests and explicit attempts are stored in the hash-chained `rumors/<campaign>` authority ledger. Evidence feasibility is checked before reserving a new request and before pinning each attempt, so rejected oversized or invalid output does not strand an operation. Attempts pin expected ordinary 020 record values before each single-record evidence append. On retry, exact committed evidence is reconciled before a newer supplied Moment is considered. Missing output may get a new audited attempt when an unrelated evidence write advanced the high-water mark; conflicting or quarantined output fails closed. A delivery already committed is reconciled even if its route is now blocked. If it was staged but absent, current conditions must permit delivery again. Reopen the authority after an incomplete or poisoned write. The ledgers are not synced by an adapter yet; future 055 integration must supply the explicit clock and serial evidence Moments. This is local crash reconciliation, not distributed exactly-once transport.
