Dossier refresh failures during absorb are reported instead of silently swallowed

base main @ 55b1022c → 16d6675a · +230/−31 · generated 2026-07-28

A silent failure path becomes a reported one

The scene-absorb endpoint refreshes a short "dossier" paragraph for every NPC present in the scene, one LLM call each. That loop caught every exception and moved on, so a rate limit, a bad character record, or a parse failure produced an absorb that looked completely successful while some or all NPC memories silently went stale. After this change absorb still never fails on a dossier error — but the response carries a dossiers block naming exactly which NPCs were refreshed, which were not, and why, and the scene inspector renders the failures.

The loop moved verbatim into backend/src/grimoire/routes.py:3116 (_refresh_dossiers), deliberately shaped like the _run_audit helper forty lines above it (backend/src/grimoire/routes.py:3075) that already solved the identical problem for the mechanics audit. No LLM prompt, no dossier content, and no call ordering changed.

What moved

  • A failure boundary was added above the loop, not just around it. scene_cast and campaign_root used to run at post_absorb's top level; they now run inside a try (backend/src/grimoire/routes.py:3122-3127). This closes a real 500 path — the one failure in the old phase that was not swallowed.
  • Each loop iteration now terminates in a value. The old except: continue became an except/else pair appending to failed or refreshed (backend/src/grimoire/routes.py:3137-3144). Every path through the loop body now writes exactly one outcome.
  • No change to LLM call count, order, or content. Same one call per present NPC with role == "npc", same build_prompt, same dossiers.write. Player-cast characters are still skipped by the same guard.
  • No change to error propagation for the rest of absorb. The extraction call's LLMError → 502 (backend/src/grimoire/routes.py:3170-3171) and _run_audit's boundary are untouched, and the dossier phase still runs strictly between them.
  • New status edge: a scene with NPCs where every dossier fails now reports failed rather than being indistinguishable from a scene with no NPCs. skipped is reserved for genuinely having nothing to do (backend/src/grimoire/routes.py:3146-3147).
Unchanged and worth noting: the dossier write is a real side effect of a "preview" call. post_absorb otherwise stages edits for the user to approve and persists nothing — that contract is asserted by backend/tests/test_routes.py:2117 (test_absorb_returns_preview_without_persisting). Dossiers have always been written to disk immediately, before the reviewer approves anything, and this change does not alter that. It does make it more visible: refreshed is now an explicit list of records that were mutated during a preview.
