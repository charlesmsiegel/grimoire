# 05-S7 The API: implementation plan

**Goal:** 05-C2 in full: `POST /api/cache/sync` as a `background` run on the
global subject, 409 `sync_in_flight`, `attempt_id` repeats, Cancel through
`stop`, and progress and final frames.

**Spec:** sections 7.8, 9, 11 (05-C2) and 13 ("The CLI and the API").

## Design

- **`routes/cache.py`**, `post_cache_sync`, a `def` handler (reserving a run
  builds its events through the portal). The body is a plain `BaseModel`
  (`paths`, `campaigns`, `worlds`, `all_records`, `renamed` as
  `[{"old", "new"}]`, `deleted`, `embed`, `dry_run`, `verify`, `attempt_id`),
  dumped through `routes.common._dump`. No selector is 400
  `nothing_to_sync`; a malformed rename is 400 `bad_rename`.
- **Reservation** — `runs.reserve_cache_sync(app, attempt_id)` calls
  `start_or_existing(..., refuse_live=True)`, a new registry option: a live
  run of the same class and kind on the subject (a stopping one included)
  refuses with `RunInFlightError`, answered 409 `sync_in_flight` with its id;
  a repeat of that run's own attempt id is handed it back (the existing
  `_by_own_attempt` lookup runs first). Nothing is adopted, so a dry run or an
  `embed: false` sent while another sync runs never spends.
- **Work** — inside `runs.reservation`, the root is pinned and the batch is
  handed to `runner.start_thread` (the never-abandoned worker thread, awaited
  shielded), `run.started` after the handoff. The work takes the registry's
  sync hold, runs `cache_sync.run(...)` with `stop=lambda: run.cancel_requested`
  and a `progress` callback that appends counts-only frames, then appends the
  report as the final frame and returns it as the run's result. A run whose
  flag was set ends `cancelled`, its report saying what ran.
- **Shutdown** — `cache_warm.stop(app)` also sets `cancel_requested` on live
  `cache-sync` runs, beside the queue's own flag.
- **Docs** — CLAUDE.md's Detached runs section: "Thirty-three handlers", and
  `post_cache_sync` in the `background` bullet.

## Tests (`tests/test_cache_sync_api.py`)

A sync answers 202 and its report is the final frame (progress frames carry
counts only); no selector and a malformed rename are 400; a second request
is refused 409 `sync_in_flight` naming the live run whatever its options, and
spends and bumps nothing, while a repeat of the first attempt id gets the same
run; Cancel stops the batch at its next check and the report says so (three
hot paths `unsynced`, the token already bumped); `PUT /config/data-dir`
answers 409 while a sync is live.
