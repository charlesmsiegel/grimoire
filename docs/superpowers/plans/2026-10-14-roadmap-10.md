# Roadmap 10 — retrieval query planning: implementation plan (S1–S3)

**Spec:** `docs/superpowers/specs/2026-10-09-roadmap-10-retrieval-query-planning-design.md`
**Baseline:** `main` at `57abb2c` (09 merged in #515).
**Gates:** plan gate, review and final gate were met by the PR's Codex review
(`@codex review` on #516), which `CLAUDE.md` accepts in lieu of the CLI gates. The
plan was written in the same session as the implementation; it records the
order the work took and what each slice's acceptance holds.

Re-read before planning, as the spec's implementation rule asks: 09 as landed
(`routes/history_recall.py`, `store/history/`), 01f (`inference.generate`'s
`schema=` and `max_tokens=`, `schemas.check`/`render`/`find_value`), 01d

(`routes/decision_capture.capturing`), and 02-S2's `routing.NO_LEGACY` and
`NO_LEGACY_TASKS`, which already exist — so 10 adds no sentinel and no
baseline mechanism of its own.

## 10-S1 — the planner and one planned round

1. `store/history/plan.py`: `Record`, `Found`, `Tried`, `PlanInput`,
   `Offered`, `Plan`; `build_input` (09's filtered seeds by part, each part
   capped), `clip` (`PLAN_INPUT_BYTES`, bottom of the table first, never the
   window), `offered`, `schema_for` (shapes only; no `enum` when nothing is
   offered), `build_messages` (the schema through `schema_json`), `read` /
   `parse` (total; every bound of 5.4), `query_of`, `tried_of`, `projection`,
   `Plan.adds_nothing_to`.
2. `templates/history_plan/system.j2` and `user.j2`; `templates/README.md`;
   the builder in `scripts/verify_templates.py`.
3. `routing.ROUTES` gains `history_plan` (Fast, `NO_LEGACY`); the
   `test_routing.py` registry assertions move with it.
4. `store/history/model.py`: `RoundRecord`, `Step`, `PlanTrace`;
   `Evidence.plan`, projected into `detail()` only when present, and copied
   onto the composer's history row.
5. `store/history/retrieval.expander`: `merge`'s lazy expansion callback for
   a scene neither round expanded.
6. `routes/history_recall.py`: `_prepare` returns the catalog and the plan
   settings; `gather` takes `force` and `final_check`, uses
   `HISTORY_PHASE_PLANNED_SECONDS` when planning may run, and hands the first
   evidence to `plan_and_repair`, which resolves in a history worker, meters
   on the post, bounds the call by `min(PLAN_CEILING, remaining)` with
   `_noting`, reads after the meter, retrieves the plan's `Query` with no
   rerank, and merges with the first retrieval's rerank opinion reapplied.
7. `history_plan` config key (store, `GET /config`, `ConfigUpdate`).
8. Tests: `test_history_plan.py` (store), `test_history_plan_routes.py`
   (routes), the cassette entry and body test in `test_llm_fakes.py`, the
   viewed-input pin in `test_regex_prompt_guard.py`.

## 10-S2 — the sufficiency check and the repair hop

1. `store/history/sufficiency.py`: `item` (one `Predicate`, no rationale),
   `verdict_of` (read True/False only; an answer only an escalation hop gave
   is `escalated`).
2. `templates/history_check/item.j2`, `question.j2`; README; the builder.
3. `history-sufficiency` appended to `history_check`; its `TaskPolicy` row
   (fallback `role`, no sampling, escalation off until evidence).
4. `routes/history_recall._sufficiency` / public `sufficient`: resolved in a
   worker, `_check_around` (each call `min(CHECK_CEILING, remaining)`, none
   after the deadline), captured through `decision_capture`.
5. The repair hop in `plan_and_repair` (`_repair`): `tried` quoted as data,
   the novelty rule, `unrepaired`, `repair_redundant`, `final_check` and
   `cheap_retrieval_failed`; `MAX_PLAN_STEPS` counted before every step.
6. `history_plan_repair` key; Settings controls in the Context pane; the
   inspector's planning lines.
7. The `decide-history-sufficiency` replay case and recordings; the
   cassette entry; `test_history_sufficiency.py`.

## 10-S3 — planning evals

1. `evals/history/planning.py`: spec 11's cases and controls on the store,
   recorded replies replayed through the real facade, four arms, validation
   replies, aggregate, offline gate and the reported default gate.
2. `evals/recordings/history/plan.<shape>.json`, `plan.validation.json`.
3. `evals/run.py --history --plan` (offline, or `--live` with 09's
   downstream grader); `evals/README.md`.
4. `test_history_plan_evals.py`: the offline run inside `pytest backend`.
