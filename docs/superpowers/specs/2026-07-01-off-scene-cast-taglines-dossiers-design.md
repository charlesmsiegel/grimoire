# Off-scene cast: taglines & dossiers — populating tiers 2 and 3

## Problem

The narrator context builder gives the off-scene cast three tiers
(`context._cast_directory`):

| Tier | Set (relative to current scene) | Form | Fed by |
|---|---|---|---|
| 1 Present | `scene_cast` | full card | campaign card (works) |
| 2 Active, elsewhere | `roster` − `scene_cast` (npc) | paragraph | brief **body** |
| 3 Known to exist | world chars − `roster` − `scene_cast` | sentence | brief **tagline** |

Tiers 2 and 3 are both fed by the `brief.md` artifact
(`store/briefs.py`) — a `tagline` + `body` paragraph derived together from a
card. But **no brief is ever created**: the frontend to view/generate/edit
briefs was deferred to a "campaign-tab redesign" (brief-tiers spec, Follow-up
#3) that never shipped, and briefs are only *populated* into a campaign when a
character appears (`appearances._copy_actor` copies an existing `brief.md`). Net
effect in a real store: **0 briefs across 67 characters**, so tiers 2 and 3 are
always empty, and a character can only become "known to exist" *after* it has
already appeared — backwards from the tier's purpose. The scene inspector
faithfully shows this (same `_assemble` path), so the sections simply aren't there.

This supersedes `2026-06-29-character-brief-tiers-design.md`. That spec's
Follow-up #2 (context-budget instrumentation) is already done — the inspector's
per-section token breakdown.

## Root cause

The single `brief` artifact conflates two things that have **different scope,
trigger, and home**, and neither is ever produced:

- The tier-3 **tagline** is world-level *identity* — the same in every campaign.
- The tier-2 **body** is campaign-level *standing* — it evolves as the campaign plays.

Coupling them into one file, generated by one call, tied to appearance, is why
the feature never populated. The fix is to split them into two named artifacts,
each with its own lifecycle, and to generate each at a natural moment that is
**not** gated on appearance.

## Design: replace `brief` with `tagline` + `dossier`

Retire `brief` entirely (it has zero data and no frontend) and replace it with
two artifacts:

| | **Tagline** | **Dossier** |
|---|---|---|
| Concept | world identity, one sentence | campaign standing, one paragraph |
| Scope | **character-level**, world (version-independent) | character-level, campaign |
| Storage | `worlds/<w>/characters/<c>/tagline.md` | `campaigns/<c>/characters/<c>/dossier.md` |
| Module | new `store/taglines.py` | new `store/dossiers.py` |
| Written by | **input-or-generate popup** at import, **by hand** (UI), or authored | LLM at **absorb** (end of scene) |
| Feeds | tier 3 "Known to exist" | tier 2 "Active in this campaign, elsewhere" |

Neither generation path runs during a context build — context builds never make
LLM calls (unchanged invariant from the brief-tiers spec).

### Tagline (`store/taglines.py`)

- **Character-level, not per-version.** Stored at
  `worlds/<w>/characters/<c>/tagline.md` — one tagline per character, above any
  version dir. Off-scene identity doesn't need the anatomy/variant distinction,
  and an in-scene character gets its full versioned card anyway.
- **Plain content, no staleness hash.** The file is the one-line sentence
  (trimmed markdown, no frontmatter). The old brief's `base`-hash staleness is
  dropped: a hand-written tagline must not silently go "stale" when a card
  changes. Regeneration is an explicit action.
- **Three write paths, one file:**
  1. **Input-or-generate popup at import.** After an import completes, the
     frontend opens a **tagline popup** for the new character asking to input or
     generate. If the user **types** a tagline it is saved via `PUT` and **no LLM
     call is made** ("avoid generating if the user provides one"). If they click
     **Generate**, `POST .../tagline/generate` fills the field (still editable)
     and they save. Skipping leaves it blank — the character stays out of tier 3
     until briefed. The import routes (routes.py:614, :629) are **unchanged**:
     they don't generate; the popup orchestrates via the tagline routes below.
  2. **Hand-input / regenerate.** New routes
     `GET /worlds/{wid}/characters/{cid}/tagline` and `PUT .../tagline`
     (`{tagline}`) read/save the file; `POST .../tagline/generate` generates via
     the LLM (`TAGLINE_INSTRUCTION`, one sentence from the default-version card).
     `CharacterEditor` shows the tagline in the detail sidebar (character-level,
     not on the version card) with an inline edit field and a Generate/Regenerate
     button. These same routes back the import popup.
  3. **Authored backfill.** The 67 existing `onboarding-sandbox` characters get
     hand-written `tagline.md` files (see Existing data). One-time, data only.
- `{{user}}`/`{{char}}` substitution runs over tier 3 as today.

### Dossier (`store/dossiers.py`)

- **Character-level, campaign-scoped.** Stored at
  `campaigns/<c>/characters/<c>/dossier.md` — a short paragraph: who the
  character is and their current standing in *this* campaign. Named `dossier`
  (not "status") to avoid colliding with the existing `# Character state`
  section, which is the in-scene gameplay state (`playstate`) of present
  characters — a different thing for a different set.
- **Generated at absorb.** `post_absorb` (routes.py:1166), after materializing
  edits, generates/updates the dossier for **each character in the scene's
  cast** via a focused prompt over the transcript + prior dossier. Only in-scene
  (hence appeared) characters get dossiers — matching "don't need to exist until
  they've appeared in-world." Wrapped so a dossier failure never fails absorb.
- **No appearance-time copy.** `_copy_actor` no longer copies any brief/dossier
  into the campaign — dossiers are born campaign-side at absorb, taglines are
  read straight from the world.

### Context assembly (`context._cast_directory`)

- Tier 3 "Known to exist" → `taglines.read(wroot, id)` (was the world brief
  tagline). Keeps the live `(available as: <versions>)` suffix computed at render
  time.
- Tier 2 "Active in this campaign, elsewhere" → `dossiers.read(croot, id)` (was
  the campaign brief body).
- Unchanged: players excluded (persona path), a character with neither artifact
  is **skipped** (not listed as a bare name), the section is omitted when empty.

### Removal

- Delete `store/briefs.py`, the three brief routes
  (`GET/PUT/POST /worlds/{wid}/characters/{cid}/brief`), and `test_briefs`-style
  brief tests.
- Remove the `brief.md` copy from `appearances._copy_actor`.
- Update `test_context.py::test_cast_directory_*` to the new artifacts.

## Existing data (one-time, not committed)

Author `worlds/onboarding-sandbox/characters/<c>/tagline.md` for the 67
characters by reading each card, so tier 3 lights up immediately in the
`quiet-hand` campaign. Dossiers need no backfill — the two already-appeared
characters get dossiers at the next absorb of their scene. This edits the user's
`~/.grimoire` store; it is data, not repository code.

## Phasing

One spec, two independently-shippable phases:

- **Phase 1 — fixes the reported bug.** `taglines.py`; tagline routes
  (`GET`/`PUT`/`POST generate`); import **input-or-generate popup** +
  `CharacterEditor` tagline field; author the 67; context tier 3 → taglines;
  remove `briefs`. Also add `dossiers.py` and point tier 2 at it
  (empty until Phase 2 — same as today). After Phase 1, not-yet-appeared
  characters appear in "Known to exist."
- **Phase 2 — the enhancement.** Generate/update dossiers at absorb → tier 2
  "Active in this campaign, elsewhere" populates.

## Follow-up (filed, not built)

**Make tier 3 "Known to exist" contextual** instead of listing every world
character — surface only characters relevant to the scene. Blocked on
groups/factions existing. GitHub issue on milestone #14 (Context Building &
Inspector), cross-referencing #11 (Cast & Appearances).

## Testing

Backend (pytest, `GRIMOIRE_HOME` tmp isolation):

- **taglines store**: read/write round-trip; missing → `""`; character-level path
  (independent of versions).
- **tagline routes**: `GET`/`PUT` round-trip; `POST .../generate` writes the
  parsed sentence via a mocked OpenRouter; import routes are unchanged (no
  generation, no OpenRouter dependency).
- **dossiers store**: read/write round-trip; missing → `""`.
- **dossier at absorb**: mock OpenRouter; absorb writes a dossier for each
  in-scene character; a dossier failure does not fail absorb.
- **context tiers**: present + roster-elsewhere (with dossier) + world-only (with
  tagline) → full card / paragraph / sentence respectively; version list appended
  to tier 3; `{{user}}`/`{{char}}` substituted; a character with neither artifact
  is skipped.
- **appear**: `_copy_actor` no longer writes a brief/dossier into the campaign.

Frontend (vitest, from `frontend/`, mock-based):

- `CharacterEditor` shows the tagline and an edit field at the character level;
  Generate calls the generate endpoint; Save calls `PUT`.
- **Import popup**: appears after import; typing a tagline and saving calls `PUT`
  and **not** the generate endpoint; Generate calls the generate endpoint;
  Skip leaves the tagline unset.
