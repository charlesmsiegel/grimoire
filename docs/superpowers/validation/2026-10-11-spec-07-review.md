## 1. Copy-on-write silently rebinds detached actor references

**Severity:** high. Original spec lines 841?845.

The detached filter applies only while a group is inherited (§7.6:841–845). An unrelated body append or another actor's join materializes the raw world file (overlay.py:650–668, 786–794), so previously filtered references suddenly identify campaign actors. Their membership can open owner gates without an approved membership row, and undoing the approved delta leaves those affiliations standing because undo never dematerializes (§9.5:1063–1065). Conversely, an explicit join for a filtered actor is skipped because edited_line already finds that actor in the raw tokens (§4.3:379–381; §9.4:1019–1020).

**Recommendation:** Define identity-preserving materialization for inherited references across every writer. Only explicit membership edits should bind detached actors. Make staging, no-op checks and undo snapshots agree on effective status, while preserving unrelated raw tokens. Test unrelated body saves, another actor's delta, explicit joins and per-actor undo under collisions.

**Correction:** Section 7.7 adds a central fail-closed materialization guard, explicit reviewed slots, atomic final text, effective status checks and collision/undo acceptance cases. No origin metadata is added.

## 2. Absorb bypasses the secret-affiliation visibility rule

**Severity:** high. Original spec lines 901?905.

The new snapshot segment applies to affiliated cast members, with only gm-only groups excluded (§9.2:901–925). snapshots.py:107–114 currently retains secret groups, and user.j2:43 renders the snapshot under a plain Groups heading. Consequently, secret membership reaches the extraction model without the framing required by §12.1:1254–1263. S7's prompt_visible helper cannot protect this S5 consumer, which never applies it.

**Recommendation:** Apply the visibility rule in absorb itself: omit secret affiliation text by default, or render secret snapshots in an explicitly secret-framed block. Move the necessary visibility primitive before S5 and add a secret-group snapshot acceptance case.

**Correction:** Sections 9.2 and 12.1 require a separately warned secret block; gm-only remains excluded. prompt_visible moves to S2 before the S5 consumer.

## 3. Fresh stamps cannot vouch for an already-populated overlay View

**Severity:** high. Original spec lines 719?721.

campaign_index accepts a caller's View (§7.2:668–670), whose gone and off properties retain previously read ledger contents (overlay.py:164–173). If another request changes a ledger before listing_stamps runs, group_listing can use the old cached contents alongside the new file stamp. Once outside the racy window, memo_stamped can retain that pairing indefinitely: later calls see unchanged stamps and reuse the stale index. The proposed separate helpers do not specify how to recover the original pre-read stamps.

**Recommendation:** Have one overlay operation return rows and stamps captured before their actual reads. Either compute with a fresh View after stamping, or carry original stamps with cached View properties and previously read listings. Test a populated View followed by concurrent detachment/tombstone changes and subsequent cache hits.

**Correction:** Section 7.3 couples rows and pre-read stamps in one fresh overlay sweep, removes the caller View parameter and refuses memo storage under mismatched roots.

## 4. The absorb snapshot erases the leader/member distinction

**Severity:** medium. Original spec lines 921?925.

A leader renders identically whether or not members lists them, and the stated purpose is to discourage a leader-only affiliate's join (§9.2:921–925). But §4.4:394–396 explicitly permits an outside leader who is not a member. If that leader is subsequently admitted, the model lacks the standing membership distinction and is instructed not to propose the join. Staging cannot recover a proposal the extraction omitted.

**Recommendation:** Render leader-only and leader-plus-member roles distinctly. Suppress redundant joins only for actual members. Add cases where an unlisted leader joins and a listed leader leaves while retaining leadership.

**Correction:** Section 9.2 distinguishes leader-only, member-only and leader-plus-member roles. Tests admit an unlisted leader and remove membership while retaining leadership.

## 5. The graph requires metadata its specified input discards

**Severity:** medium. Original spec lines 1126?1135.

Group nodes require group_type (§10.2:1126–1128), but phase C reads only campaign_index (§10.3:1132–1135). Roster has no group_type (§7.1:635–641), and neither the index nor its digest retains it. The graph therefore cannot produce the specified node from this interface without another store read, dropping the field, or changing the index contract.

**Recommendation:** Add group_type to Roster and its digest, updating C2 guarantees and digest tests, or specify a shared listing that supplies graph metadata within the promised single read.

**Correction:** Sections 7.1, 7.2 and C2 retain group_type and include it in the digest and graph payload.

## 6. Dangling-actor queries have contradictory API semantics

**Severity:** medium. Original spec lines 814?816.

A valid group may name an actor before creation or after deletion (§4.2:336–338). The index explicitly retains those affiliations and answers stored membership without existence checks (§7.2:691–695). Yet ?actor= promises no groups for that same nonexisting actor. A direct groups_for lookup contradicts the route promise; an existence-filtered route adds an unstated read and answers differently from the unfiltered by_actor payload.

**Recommendation:** Make actor queries return stored affiliations for every syntactically valid ref, consistently with C2. If existence filtering is intentional, explicitly specify its route-only overlay reads and differing semantics. Add tests for referenced actors that are absent, deleted or tombstoned.

**Correction:** Section 7.5 returns stored affiliations for every syntactically valid actor query, consistently with the unfiltered inverse index.
