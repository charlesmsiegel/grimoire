# S2 membership theory

Group frontmatter alone authors current membership. Leadership and explicit
membership are independent roles; dangling references remain meaningful stored
facts. The inverse is a serializable projection, never a second roster, actor
knowledge, history, or authority to copy a foreign identity.

`group_inventory` carries bytes and pre-read provenance without overlay policy.
`entities` owns World collection capture; `overlay` owns a fresh campaign View,
strict frozen ledgers, native source selection and the shared S1 detachment rule.
Actual filenames and source layers override forged metadata. The existing
frontmatter parser, group-ref parser, native identity proofs and stamped cache
are reused. Read failures propagate instead of reporting a partial collection.

A bounded private scope memo saves parsing and inversion. Current content and
strict identity availability still require I/O on every hit. Its Pydantic wrapper
keeps the roots and digests that produced its rows; native proofs use only actor
directory identity. No later fingerprint can certify old rows. Validation covers
the actual returned wrapper because a different reader can publish after our
initial pool inspection. A mismatch returns one fresh uncached computation,
without retrying. Every caller owns a deep copy, including the first miss.

The pure inverse shares one implementation across World/campaign readers.
Capture differs at the owner where inheritance is decided, rather than
repeating parsers or allowing higher-level membership to author overlay policy.
Tests are a floor: the concrete failure cases include restored complete stat
signatures, unreadable ledgers and directories, a switched World, conflicting
thread publication, mixed native policies and mutation of returned nested models.
API/page projection and full S2 review evidence will be added as those tasks land.

The HTTP surface constructs plain response models from the same inverse. Full replies preserve every roster field; actor replies project group label/secrecy and independent roles without loading actor records. The literal router precedes generic entity kinds, and both scope clients encode actor query values. Schema/route-order tests supplement exact JSON assertions.

Both actor pages share ActorGroups. Loaded answers carry scope and actor identity so prior chips disappear synchronously on navigation; cleanup prevents late success/failure from replacing another actor. The section offers same-scope group links, with leadership labelled independently of membership. Empty/unavailable projections render no section. Focused page/component tests cover the actual integration and late-response states.
