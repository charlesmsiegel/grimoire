Break the five-file module-editor import cycle by extracting shared helpers

base main @ 55b1022c → 6d5042e8 · +284/−124 · generated 2026-07-28

Nothing executes differently. A module boundary moved.

Four shared exports — SaveFn, useModuleDryRun, ErrorList, ImpactConfirm — leave frontend/src/components/ModuleEditor.tsx for a new frontend/src/components/moduleEditShared.tsx, and all five module-editor files now import them from there. Previously ModuleEditor.tsx imported the four section components while each section imported these helpers back out of ModuleEditor.tsx: a five-file cycle. Bundlers resolve such a cycle, so no user-visible bug was being fixed — what changes is that module initialization order is no longer load-order dependent and each file can be read, and tested, on its own.

The remaining 157 lines are a new test that builds the repo's real import graph and fails if any module-editor file can reach itself.

The helper block moved byte-for-byte. Lines 13–128 of frontend/src/components/ModuleEditor.tsx at the merge base are character-identical to lines 4–119 of frontend/src/components/moduleEditShared.tsx — verified by extracting both ranges and diffing them, empty output. Every subtlety the original comments guard (the revision counter that discards superseded debounced dry-runs, the deliberate silent drop of a superseded Save click, reset() for the post-rename stale-result case) is preserved because nothing was retyped. A reviewer does not need to re-read those 116 lines; they need only confirm the import edges.

The test is the thing to review

It is not a grep. It reads every src/**/*.{ts,tsx} source through import.meta.glob(..., "?raw") (frontend/src/components/moduleEditShared.test.tsx:14), scans each with TypeScript's own preprocessor (frontend/src/components/moduleEditShared.test.tsx:55), resolves relative specifiers into a graph, and asks per entry point whether a path leads back to itself (frontend/src/components/moduleEditShared.test.tsx:117). Three properties make it worth its size:

  • It is verified red. Restoring the five pre-fix sources makes it fail five times, each naming its own participant, e.g. cycle: ModuleEditor.tsx -> ModuleSchemaEditor.tsx -> ModuleEditor.tsx. A guard nobody has watched fail is a guard nobody should trust.
  • It cannot pass vacuously. frontend/src/components/moduleEditShared.test.tsx:133 asserts the glob actually found all six module-editor files, so a broken glob fails loudly instead of silently checking nothing.
  • It cannot silently lose edges. frontend/src/components/moduleEditShared.test.tsx:146 asserts that every relative specifier which failed to resolve merely looks like an asset. This is the part that earns the file's length — it caught a live bug in the author's own resolver during development.
frontend/src/components/moduleEditShared.test.tsx — the bug that assertion caught
- const dirOf = (path: string) => path.slice(0, path.lastIndexOf("/")); + function dirOf(path: string): string { + const cut = path.lastIndexOf("/"); + return cut < 0 ? "" : path.slice(0, cut); + }

With the original line, a root-level file such as frontend/src/App.tsx has no /, so lastIndexOf returns −1, slice(0, -1) yields "App.ts", and every import in frontend/src/App.tsx and frontend/src/main.tsx resolved from a directory that does not exist — contributing zero edges to the graph. A cycle-detector with a silent hole in it is the exact failure mode this whole PR exists to prevent, and only the completeness assertion exposed it.
