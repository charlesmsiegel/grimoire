What this actually changes

POST /campaigns/{cid}/scenes/{sid}/absorb gains a phases array — one row per LLM-backed step (extraction, dossiers, audit) carrying status, reason, and two new booleans: attempted (did a request reach the model) and budget_exhausted (is this absorb's shared wall-clock budget why it did not). The same two booleans are added to the existing dossiers and mechanics blocks, which the phase rows are projected from — see backend/src/grimoire/routes/scenes.py:279.

One behavioral change beyond reporting: the audit now checks the budget before issuing its request (backend/src/grimoire/routes/scenes.py:338) rather than letting _Budget.run fail the call. Same outcome (status: "failed", retry offered), different reason text, and it is what lets the response distinguish "never attempted, the clock ran out" from "asked, and it went wrong".

In the UI, an absorb that was cut short says so once, up front (frontend/src/routes/CampaignView.tsx:849), and the two existing notices stop calling an unattempted phase a failure.

bugfix — an observability gap, not a new feature. No new endpoint, no new config, no storage format touched. Additive to one response body plus two nested blocks.

Follow-up to the same visibility work as #236 (dossier failures were silent) and #243 (the shared budget), which the code already cites.

What moved

  • One call fewer on the exhausted path. The audit no longer builds client.complete(...) for _Budget.run to cancel; it returns before that (backend/src/grimoire/routes/scenes.py:338). No behavior a user sees, but it removes a coroutine created only to be cancelled.
  • The audit's budget reason text changed from "audit failed: absorb time budget exhausted" to "the absorb time budget ran out before the audit could run". The existing regression test asserts only that "budget" appears, so it still holds (backend/tests/test_routes.py:2933).
  • Mid-flight cancellation stays attempted. A dossier call the clock kills after it went out is flagged budget_exhausted but not un-attempted (backend/src/grimoire/routes/scenes.py:433) — the distinction is exercised at backend/tests/test_routes.py:3125.
  • The retry path now maintains the projection. retryAudit rewrites the audit phase row alongside mechanics (frontend/src/routes/CampaignView.tsx:610); without it the notice outlived the condition it described.
  • Unchanged: error propagation, the 502 on extraction failure, lock scope, the commit_token replay guard, and every staged edit.

The projection design — phase rows derived from the blocks rather than tracked alongside them — is what keeps this from becoming a second source of truth, and it is pinned by a test (backend/tests/test_routes.py:3088). The dossier loop's budget check is stale by the time the call is made — the character read, the dossier read and the prompt build all happen after it — and wait_for cancels a task before its first step, so a budget that expired during those reads sends nothing while the flag said otherwise. That is a wrong value in the field this whole change exists to add. Re-checked immediately before the call (backend/src/grimoire/routes/scenes.py:421); the test asserts the model was never called alongside the flag, so it pins the mechanism rather than the symptom (backend/tests/test_routes.py:3162).
