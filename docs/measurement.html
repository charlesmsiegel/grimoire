Measurement coverage

Importance-weighted measured things over measurable things. It says how much of what matters is actually measured — not whether the code is correct.

46% of the weight that gates a ship decision is soundly measured. The headline score averages every importance level; this line is the cut that decides releases.

This audit asks a different question from the Health page beside it. Health measures how dense the detectable defects are; this measures how much of what matters here is actually measured. A package can score well on one and null on the other, and both can be honest.

grimoire is unusual in a way that makes the question sharp. Most of what it does is produce LLM prose, and a large share of the backend exists only to shape that prose — the style chain, the length budget and its drift correction, the natural-prose block, scene-suggestion grounding, the roll-fence protocol. Every one of those is a hypothesis about model behaviour, and because prompt text lives in templates and is rendered at request time, any of them can be changed with no code edit, no restart, and no failing test.

The repository knows this. evals/README.md states the gap in almost those words and builds four pass/fail cases to close it, with a design decision worth crediting: every grader reuses the production parser that consumes model output rather than reimplementing it, on the stated grounds that an eval which parses output its own way would go green through exactly the regression it exists to catch. That is a better instinct than most measurement code has.

What holds the score down is the gap between the harness and a measurement. Offline replay scores thirteen recordings that were written by hand rather than captured from a model, so it verifies the graders, not the hypotheses. The live mode that would answer the real question exists, costs money per run, is absent from CI, and has never produced a recorded baseline. Alongside that sits the plainest finding here: the backend has no coverage instrumentation at all, so 4,708 tests over the code that guarantees a transcript is never lost have never been asked what they miss — in a repository whose frontend config argues carefully about why one coverage provider is more honest than another.

Credited on the other side: the architecture guards are real measurement of a design property, the frozen-campaign fixture is a genuine backward-compatibility regression test, and the token accounting is careful to keep “nobody counted” distinct from zero — the exact trap this kind of audit is looking for.

high no_live_baseline

The eval baselines are hand-authored, so replay cannot detect a model behaviour change

All 13 recordings under evals/recordings were written by hand rather than captured from a model. Offline replay therefore proves that the graders still parse output the way the app does — which is genuinely valuable and well designed — but it cannot detect that a model, a model version, or a reworded prompt has changed compliance. The suite's own README is explicit that only --live answers that question.
