Lift the path-escape guard into paths.safe_id and apply it in the campaign/world/character/PC root resolvers (#240)

base origin/main @ 55b1022c → fix-240-safe-id-guard @ a8e618fd · +296/−143 · generated 2026-07-28

Four path resolvers stop trusting their caller — and one of them changes meaning

Every id-to-path resolver in the store now routes through a single guard, backend/src/grimoire/store/paths.py:114, which rejects ids that don't name a direct child of their parent directory. Four resolvers that previously joined a caller-supplied id onto a path unchecked — campaign_root, world_root, characters._char_dir, pcs._pc_dir — now raise their own NotFound instead.

The guard is also stricter than any of the copies it replaces except one: it rejects :. That was sheets._safe_part's idea and the other nine copies missed it. It is not cosmetic on this project's primary platform — Path("store/worlds") / "C:evil" evaluates to C:evil, because a Windows drive-relative id discards the base path entirely. Neither a / nor a \ check catches that.

The second-order change is the one to actually review: an empty world id used to be load-bearing. Five call sites passed meta.get("world", "") to mean "this campaign has no world" and depended on world_root("") resolving to the worlds parent directory. Rejecting "" would have broken all five, so they move to a new world_root_or_missing (backend/src/grimoire/store/worlds.py:45) that returns a path which cannot exist.

Two flows move; everything else is a rename

Thirteen of the nineteen files change only which function name they call. Two runtime flows genuinely change shape: resolving a record id to a path, and resolving a campaign's world root when the campaign has no world.

What moved

  • New failure mode on a previously-succeeding path. Four resolvers can now raise where they previously always returned a Path: backend/src/grimoire/store/worlds.py:32, backend/src/grimoire/store/campaigns.py:23, backend/src/grimoire/store/characters.py:33, backend/src/grimoire/store/pcs.py:33.
  • Error propagation is unchanged for HTTP callers because each resolver raises its own domain NotFound, which routes already map to 404 (21 except CampaignNotFound handlers in backend/src/grimoire/routes.py alone). The single exception is _world_root_or_404, which called world_meta_path (and thus world_root) outside any handler — fixed at backend/src/grimoire/routes.py:1826.
  • Return-None contracts preserved by short-circuit ordering. characters.dir_hash (backend/src/grimoire/store/characters.py:301) and card_hash (backend/src/grimoire/store/characters.py:279) must keep returning None, not raising, for a bad id. They still do, because not safe_id(cid) is evaluated before the _meta_path/_card_path call that would hit the raising resolver. This ordering is now load-bearing and undocumented — see the walkthrough.
  • CLI scripts change from silent misbehavior to a clear exception: backend/scripts/ingest_scene.py:31 and backend/scripts/redownload_chub.py:43 are precisely the non-router callers the issue names.

What moved

  • Same outcome, different route. Both versions surface "the world holds no records". The old one got there by scanning a real directory that happened to contain no <kind>/<id>.md files; the new one never touches the filesystem in a meaningful place.
  • One observable behavior does flip: wroot.exists(). It was True, it is now False. campaigns.ensure_campaign_slim (backend/src/grimoire/store/campaigns.py:143) branches on exactly that, so a world-less campaign stamped world_copy: full now skips migration instead of running it against the worlds dir. That is the correct behavior — there is nothing to slim against — and backend/tests/test_path_guard_store.py:133 pins it.
  • Five call sites migrated, all of them the meta.get("world", "") idiom: backend/src/grimoire/store/overlay.py:31, backend/src/grimoire/store/campaigns.py:143, backend/src/grimoire/store/migrations.py:87, backend/src/grimoire/store/sheets.py:521, backend/src/grimoire/routes.py:3317.
  • The riskiest of the five is sheets.seed: it built world_root("") / "sheets" / mid, i.e. store/worlds/sheets/<mid> — a path directly under the store root that a user could plausibly create. It only reads, so this was latent rather than live.
No flow gains an external call, a lock, or a transaction boundary. safe_id is a pure string predicate with no I/O, called on paths that already do filesystem work; the added cost is not measurable.

Verdict: mergeable. One design choice to sign off on, two nits.

The fix addresses the root cause rather than the three named symptoms — collapsing ten near-duplicate guards into one is the whole point, since the copies nobody made were exactly the resolvers that lacked the guard. The refactor is broad (13 of 19 files) but mechanical and fully covered by the existing suite. The honest objection: a sentinel filename is a weaker guarantee than a type. Nothing stops a user from creating ~/.grimoire/worlds/.none/ by hand, at which point every world-less campaign would inherit its records. The honest defense: the alternative — threading Path | None through overlay.wroot_of's 25 call sites — is a far larger and riskier diff for a case that is already an anomaly, and the sentinel is strictly better than the status quo it replaces (the worlds parent dir, which is guaranteed to exist and holds every world). Verdict: accept, but this is the line to read twice.
