# Troubleshooting

[Documentation](../README.md) · [Getting started](getting-started.md)

## Start with the failing operation

Keep the launcher terminal visible, read the app's error, and identify whether
the failure is starting the server, loading the UI, contacting a model or saving
local state. The checks below target those different boundaries.

| Symptom | What to check |
|---|---|
| Installer stops before installing packages | Python is 3.11+ and Node is 24+ in that terminal |
| Browser opens an old development address | Normal launch uses port 8173; port 5173 is the development UI |
| UI looks unchanged after updating | Read the launcher's rebuild result; rerun the installer if dependencies changed |
| UI opens but generation is unavailable | Check the effective Primary role, provider credentials, model ID and capability refusal |
| Local provider has no listed models | Confirm its address and `/models` support; enter a known model ID if the endpoint has no catalog |
| Provider check succeeds but a turn fails | Run the explicit model test and inspect the capability/request error |
| Phone cannot reach a local model | Use the computer's network address, not the phone's localhost; check the model server's bind address |
| The library appears empty | Check Storage and the launching environment's `GRIMOIRE_HOME` before creating replacement records |
| Record changes are not used in a campaign | Check whether the campaign has its own diverged record |
| A prompt omits expected information | Inspect activation, exclusions, actor knowledge and packing in Context |
| A scene refuses edits as busy | Inspect its active run; wait or use cancellation before changing its structure |
| A review is stale | Prepare it again after transcript changes instead of forcing an old result |

## A request timed out or the page disconnected

A browser disconnect does not cancel a server-owned run. Reopen the scene and
check its status before sending the same action again. An active turn can still
finish while the browser is elsewhere. A process crash or app shutdown is a
different boundary; retained transcript and attempt records help recovery, but
the process-local run registry does not restart the model call.

If a slow local model hits a timeout, inspect the timeout controls in
Configuration and whether the provider is responding at all. Increasing a limit
does not fix an incorrect model ID, unsupported request or authentication error.

## Settings report an upgrade or newer format

An older library's model settings are migrated separately from normal play.
The settings page can wait for an unfinished upgrade. Preserve the migration's
safety archives and read its reported failure before retrying.

A `newer_format` refusal means this build cannot safely write those settings.
Use a compatible newer build; do not erase the format marker or hand-copy legacy
keys into current settings. [Storage contracts](../reference/storage.md#model-settings-migration)
explains the safety boundary.

## Logs and incoming model responses

**Stats** exposes recorded errors and measurements. Structured logs live under
the active library's `logs/`, in monthly JSONL files. Usage is a separate ledger;
an error count for all app failures and one for model calls need not agree.

At Debug level, adapters can capture incoming model response bodies, including
reasoning. Large bodies are split into numbered parts. These logs help distinguish
an empty response, parser failure and provider refusal, but can contain private
story content echoed or generated by the provider. Review and redact them before
sharing. Request URLs, headers and bodies are not passed to this capture sink.

Capture is diagnostic, not a permanent complete network recording: log limits,
disabled Debug logging, interrupted calls or unavailable response bodies can
leave gaps. Prompt history records the composed input; response capture records
incoming output. Neither substitutes for the other.

To reconstruct an incoming event from exported JSONL logs:

1. Select rows whose `kind` is `llm_incoming`.
2. Group by `call_id`, `attempt` and `sequence`. An attempt may have an optional
   `run_id`, but one run can contain multiple calls.
3. Within each group, check that every numbered `part` through `parts` is
   present, sort by `part`, and concatenate `payload` strings.
4. JSON-decode the joined string once. Do not decode individual fragments.
5. Order the reconstructed events by `sequence` within that call's attempt.
   `elapsed_ms` is relative to the attempt, not a clock shared by all calls.

Inspect `start`, `end` and any `log_capped` marker when assessing completeness.
SSE lines, whole decision/error bodies and SDK messages have different event
types; preserve their framing rather than treating every payload as prose.

## Image maintenance is blocked

Read the maintenance report. Unreadable placements, missing synced objects,
unknown formats, recent staging work and a missing recycle bin can prevent
collection. Let syncing or active imports finish, resolve the named problem,
then scan again. Do not bypass the scan by deleting shared image files manually.

## Report a reproducible problem

Include the operation, expected result, actual error, platform and source revision.
Use synthetic records or the [isolated verification workflow](../reference/development.md#verify-without-a-private-library)
to reproduce it. Do not attach a real library, credential file or unreviewed
screenshot. If a check could not run, name that limitation instead of reporting
it as passing.
