backend/tests/test_module_references.py sound, one hardening gap

The right instinct for a docs bug — it converts "someone should have noticed" into a failing test, and it was demonstrated to fail on the pre-fix tree rather than merely asserted to. Three design properties are worth a reviewer's attention:

Should-fix — the guard can pass vacuously if the package is ever imported from a non-editable install. backend/tests/test_module_references.py:18 derives the search root positionally:
backend/tests/test_module_references.py — lines 17–18
PKG = Path(grimoire.__file__).parent # backend/src/grimoire BACKEND = PKG.parents[1] # backend/

That comment is only true for a source checkout. Imported from site-packages, PKG.parents[1] becomes the environment root, and _known_modules() (backend/tests/test_module_references.py:24-26) then rglobs every installed third-party .py into the known-set — at which point almost any name resolves and the assertion quietly stops testing anything. A guard that fails loudly when its assumptions break is fine; one that passes silently is the failure mode it was written to prevent. One line fixes it: assert (BACKEND / "pyproject.toml").exists() before scanning, so a wrong layout errors instead of green-lighting.

Not currently reachable — the repo's venv installs editable and CLAUDE.md pins worktree runs to PYTHONPATH=backend/src — so this is a robustness fix, not a live bug.

Nit — resolution is by basename, so it proves existence, not correctness. backend/tests/test_module_references.py:36 checks name not in known, a set of bare filenames. A docstring naming dossiers.py would pass even if the intended module lived in a different subpackage, and a hypothetical calendars/briefs.py would have satisfied the original bad reference. Defensible — prose says "mirrors dossiers.py" without a path, so a path-accurate check would demand prose the codebase doesn't write — but the test's docstring should say so, since "references a module that exists" is a weaker guarantee than the test name suggests.
Nit — the regex scans all source text, not only comments and docstrings. backend/tests/test_module_references.py:21 matches any <name>.py token, including one inside a string literal. No false positives exist today (22 references, all resolving), and catching a stale filename in a literal is arguably a feature; but the first legitimate reference to an external script will fail this test and need an allowlist. Cheap to live with, worth knowing.
