# Sourced memory

`grimoire.memory` builds a disposable, bounded view of exact confirmed evidence held by one actor. Selections accumulate in independent named collections. Corrections link obsolete evidence to later replacement evidence, suppressing the obsolete item even if a later selection repeats it. Competing evidence is retained. A view includes history and replacement links, unavailable IDs, and an omitted count; it does not create beliefs, summarize events, or copy excerpts into the memory ledger. Evidence is resolved again on every read. `as_of` uses campaign knowledge sequence, not elapsed time.

`MemoryLibrary` stores operations in `authority/memory/<campaign>` through `DurableAuthority`. The current sovereignty controller must request each operation. A human controller uses their own trusted issued handle; director operations require an explicit director perspective on a trusted service handle. Control is checked again on each operation. Current actor views apply only the present controller's operations; `inspect` is a separate director audit of all recorded editors and provenance. The executor remains responsible for authenticating callers and protecting director access.

IDs are campaign-qualified through the actor reference. Operation IDs are unique within the campaign. An exact retry by the same principal and editor is a no-op; changed payloads conflict. Batches contain 1–500 distinct evidence IDs. View limits default to 100 and range from 1 to 1000. Evidence must be confirmed and held by the actor at the operation moment; all replacement evidence must be later than every obsolete item. Corrections cannot compete for the same old ID within one editor's history. Moment order cannot decrease within an actor/editor history. Source evidence and beliefs are never modified.

The ledger is a headless local contract. It has no context-pack, UI, or sync adapter. The caller must include `memory_actor_ids` in campaign ID reservation. This is bounded-view behavior, not a claim of million-word performance. The current evidence projection carries exact excerpt, kind, channel, moment, proposition and attribution, but does not expose additional uncertainty fields not present in `KnownEvidence`.
