Judge 1

Theory: An evaluation is a hypothesis exercised on synthetic state through the same prompt builders and inference operations the application uses, with explicit checks and counterexamples. Replay validates parsing and the checks themselves; opt-in live runs observe model behavior and attribute cost inside a temporary library without converting one output into a quality guarantee.

Instead of: A benchmark of hand-written prompts and a single headline score would be easier to run, but could measure prompts the product never sends and hide unfailable graders; this unit binds cases to production builders and declared counterexamples.

Judge 3

Theory: An evaluation is a controlled synthetic situation passed through production prompt/retrieval machinery, then assessed by explicit behavioral checks with counterexamples. Offline replay establishes parser, prompt-contract and grader behavior, while opt-in live runs collect empirical model outcomes and cost without conflating those two questions. Retrieval families hold packing and eligibility fixed while ablating the signal under study.

Instead of: A single benchmark score for narrative quality would be another reading, but the implemented Case, Check and recording expectations measure named contracts and failure sensitivity; replay deliberately makes no claim about current model behavior.
