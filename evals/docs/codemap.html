Four pass/fail questions about what the model actually writes

evals is 868 lines across five modules, and it is the only thing in this repository that tries to check a hypothesis about model behaviour rather than about code. Its own README states the gap it closes: much of the backend exists to shape LLM prose — the style chain, the length budget, drift correction, the roll-fence protocol — and every one of those is a hypothesis, while a template edit takes effect live with no restart and no code change.

It is deliberately not a framework. Four cases, thirteen checked-in recordings, no human judgement, and no LLM judge.

The design decision worth copying. Every grader reuses the production code that consumes model output — split_reply, length_drift.measure, FenceWatcher, absorb.extract_object — rather than reimplementing the parsing. evals/graders.py states the reason: an eval that parses output its own way stops testing the app the moment the app's parser changes, and would go green through exactly the regression it exists to catch. The one deliberate inversion (grade_absorb scores the raw object) is documented with its reason.
The limit, which the package states itself. Offline replay proves the graders still score recorded output correctly and that the instructions still appear in the assembled prompt. It cannot prove a model obeys a reworded instruction — only --live answers that, and it is opt-in, absent from CI, and its baselines are hand-authored rather than recorded from a real model. The Measurement page grades this in full.
